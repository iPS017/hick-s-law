## What conversion means here

In onboarding the "purchase" is the activation event: the first action that delivers the product's core value (first project created, first invoice sent, first integration connected). Define it before auditing. Every screen between signup and that event is a cost.

## Rules

1. **Map the shortest path to the activation event** and remove every step that is not on it. Settings, profile, team invites and integrations can usually come later.
2. **One question per screen** in welcome surveys, with visual cards for answers.
3. **Only ask what changes the path.** If an answer does not change what the user sees next, do not ask it now. Canva's widely cited example asks one question ("What will you design?") and reshapes templates and suggestions from it.
4. **Start from a template or sample data, not a blank canvas.** A blank canvas is the largest open decision in a product.
5. **Smart defaults everywhere:** preselected workspace name from the email domain, default timezone and language from the browser, a default project ready to use.
6. **One next step at a time.** A checklist is fine if it is short (three to five items) and the next item is highlighted. Do not show the full feature tour upfront.
7. **Progressive disclosure for advanced features:** reveal them when the user reaches a point where they are relevant (contextual tips, empty states that teach).
8. **Plan choice after value, when possible.** For trials, ask for the plan or payment when the user has hit the activation event or near trial end, with a recommended plan based on their usage.
9. **Upgrade prompts are decisions too.** Trigger them at the limit the user just hit, with one recommended upgrade, not the full pricing grid.
10. **Skip is a valid option.** Let users skip optional setup steps without penalty.

## Audit questions

- What is the activation event? How many screens and decisions separate signup from it?
- Which questions in the welcome flow change nothing for the user?
- Does the user land on an empty state or on a ready template?
- How many items does the onboarding checklist show at once? Is the next one obvious?
- When is the user first asked to pick a plan or pay? Before or after value?
- Which settings could get a default from data already known?

## Test ideas

- Welcome survey with one routing question vs current survey.
- Template-first start vs blank start. Watch time to activation event.
- Checklist of three items vs current list.
- Upgrade prompt with one recommended plan vs link to the pricing page.
